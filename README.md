# SLA court for paid APIs

<img src="sla/logo.png" alt="" width="96" align="right">

A GenLayer Intelligent Contract that rules **refund / no_refund / could_not_decide** on a paid x402 API call, with a reason from a closed set: `no_response`, `stale_data`, `schema_mismatch`, `wrong_resource`, `delivered_ok`, `insufficient_evidence`. A buyer paid, says the answer was bad, and the court decides from a settled payment and the seller's signed receipt. Seller in the demo: AgentFeed (x402.ochinimus.app).

- **Live page:** https://mandatecourt.ochinimus.app/sla/ (pick a case, press Judge, watch the transaction on studionet)
- **Deployed contract (studionet):** `0x49838F1Bfe771bDF20186C6c07a8E436680a1e69`
- **Report:** [REPORT-sla.md](REPORT-sla.md) · **Signer deploy steps:** [sla/SERVER-STEPS.md](sla/SERVER-STEPS.md)
- **Licence:** MIT, author seekdaseek. Built on the library code of MandateCourt (https://github.com/seekdaseek/iussum-genlayer).

## What it decides

1. **Plain code first.** Size, run tag, JSON, schema, canonical form, hash.
2. **The seller's receipt.** ed25519 over `iussum-sla/0.1 receipt` plus canonical JSON; the seller key is pinned in the constructor. It binds the payment tx, the tool, the resource asked for (with query), the HTTP status, the time served and the sha256 of the answer.
3. **The payment, read by every validator from chain RPC** (Solana mainnet or Base, one request per transaction): success, amount at or above the tool's price, payee, USDC mint, served within 30 s before to 600 s after the block time. Any failure ends the case there as `could_not_decide / insufficient_evidence` with a refusal code.
4. **What "delivered" means, per tool, in code** (`get_sol_price`, `get_btc_price`, `get_funding_rate`): HTTP status and body, schema, the asset named in the answer against the resource asked for, and the age of the data (`publish_time`, or `next_funding_time` for funding) against the SLA. Most cases end here.
5. **The grey zone only goes to the model jury:** data older than the promised 120 s and not older than the 600 s hard limit. One question, closed answer set, evidence is signed facts plus the seller's live `/api/status` fetched by each validator. Validators must agree on verdict and reason.

The buyer's complaint and the response body are never shown to a model. `contracts/sla_court.py` is generated by `sla/gen_sla_contract.py` from `sla/sla_court.template.py` plus functions lifted byte for byte from `contracts/mandate_court.py` (the MandateCourt library); a test checks they are identical.

## NOT VERIFIED (read this before relying on any of it)

- **Stand-in seller key.** AgentFeed has no signer deployed, so every receipt is signed with a stand-in key. `sla/agentfeed-signer/sla-signer.cjs` is the flag-gated signer; it is **not deployed**. Steps for the server: `sla/SERVER-STEPS.md`. Only its `server.js` edit was tested, on a scratch copy.
- **Fixture bodies.** The seven payments are real settled mainnet USDC transfers to AgentFeed's treasuries, read from chain. The response bodies are fixtures shaped like AgentFeed's published samples, paired with each payment by the case builder; they are not what those calls returned.
- **Wrong payee is unit-tested only.** No real treasury-history payment goes to another payee, so wrong payee, wrong mint and low amount have no on-chain case. The over-window case is a real payment with a receipt dated a day later.
- **Model path: one case, 3 runs** (all refund / stale_data, one with a rotation). No accuracy claim. A mixed HTTP 429 between leader and validators is untested.
- The 120 s soft and 600 s hard age limits, the funding rule and the payment window are the author's choices from AgentFeed's schema and `/api/status`, not published AgentFeed SLAs.
- Not tested: Bradbury, fees, appeals for this contract.

## Run the tests

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/pytest tests/sla                 # contract tests (models and RPC mocked) and library-reuse checks
.venv/bin/genvm-lint check contracts/sla_court.py
node --test tests/sla/signer.test.mjs      # signer, incl. verification by the court's own python verifier
```

The first pytest run downloads the GenVM v0.2.16 runtime (network needed). `python3` must be on PATH for the signer test. Scripts that touch studionet (`scripts/sla-run.mjs`) need `npm install` and a throwaway key in `.secrets/testnet.key` (created on first use, not in git). Rebuild the cases with `node sla/mkcases.mjs` (reads mainnet RPC, creates `.secrets/sla-seller.seed`; the public key changes, so the stored results then no longer match).
